# 论文订单管理系统当前进度说明

## 1. 当前版本定位

当前项目已经完成一个可直接使用的前端原型，重点服务于教务老师端口，适合在本地浏览器或局域网内进行试用和流程演示。

当前技术形态：

- 前端静态页面
- 浏览器 `localStorage` 本地存储数据
- 无后端数据库
- 无正式多角色权限系统

## 2. 当前已完成模块

### 2.1 登录与入口

- 已提供教务演示账号登录
- 当前主入口为本地 `index.html`
- 已支持通过本地静态服务在局域网内访问

### 2.2 订单录入

订单录入页已经按业务重新整理，支持以下板块：

- 基础信息
  - 订单编号
  - 客户姓名
  - 学历层级
  - 专业方向
  - 所需区位
  - 文章用途

- 作者信息
  - 作者登记表上传
  - 个人信息登记表状态
  - 传递给老师时间
  - 基金信息
  - 投稿邮箱
  - 投稿邮箱密码
  - 第一作者、第二作者及更多作者动态添加
  - 每位作者支持：
    - 作者姓名
    - 作者邮箱
    - 作者学历
    - 作者学校
    - 邮编
    - 作者信息（英文）

- 投稿信息
  - 操作方式
    - 一稿一投
    - 两稿两投
    - 三稿三投
  - 根据操作方式自动展开 1 到 3 组投稿信息
  - 每组支持：
    - 论文名称
    - 投稿期刊
    - 投稿网址
    - 投稿账号
    - 投稿密码
    - 投稿时间
  - 是否查重

- 人员与进度
  - 派单老师
  - 接单老师
  - 负责教务
  - 老师电话
  - 老师稳定性
  - 创新点审核
  - 初稿审核
  - 编辑老师审查
  - 作者信息核对
  - 论文进度
  - 订单阶段
  - 下次跟进时间
  - 风险等级等

- 状态信息
  - 当前真实阶段
    - Submitted
    - With Editor
    - Under Review
    - Revision
    - Accepted
    - Proofing
    - Online
    - Indexed
    - Rejected
  - 各阶段预计产出时间
  - 首周查稿时间
  - 下次查稿时间
  - 催稿信状态
  - 返修状态
  - 版面费状态
  - 校稿状态
  - Online 状态
  - 检索状态
  - 检索审查报告

- 财务信息
  - 订单额
  - 订单已付款
  - 订单待支付
  - 老师接单价格
  - 老师已付款
  - 老师待付款

### 2.3 表单导航

订单录入页顶部已加入表单内导航，可快速跳转到：

- 基础信息
- 作者信息
- 投稿信息
- 人员进度
- 状态信息
- 财务信息

### 2.4 全部订单页

全部订单页已支持：

- 一行一个订单查看概览
- 搜索订单
- 按进度筛选
- 直接快捷修改以下关键字段：
  - 论文进度
  - 接单老师
  - 稿件状态
  - 登记表状态
  - 下次跟进时间
- 一键进入详情
- 一键进入完整编辑

### 2.5 订单详情页

订单详情页已支持：

- 基础信息查看
- 多作者信息查看
- 投稿信息查看
- 教务流程进度查看
- 投稿后状态跟进查看
- 下一步教务待办查看
- 风险提醒查看
- 附件查看与下载
- 催办记录与老师反馈时间轴

### 2.6 教务工作台

角色工作台已和当前订单结构适配，能自动生成待办：

- 作者信息待补
- 投稿信息待补
- 状态节点提醒
- 老师与审核提醒

当前工作台会重点关注：

- 作者登记表是否收齐
- 作者信息是否完整
- 投稿信息是否按一稿一投 / 两稿两投 / 三稿三投填完整
- 是否查重是否已确认
- 是否分配接单老师
- 新老师是否完成创新点审核
- 初稿审核、编辑老师审查是否完成
- 投稿后一周是否进入 Under Review
- 每周查稿是否到期
- 当前真实阶段是否超出预计产出时间
- 返修、录用、校稿、online、检索等后续节点是否需要提醒

### 2.7 稳定老师库

已新增独立“稳定老师库”页面，支持：

- 老师姓名
- 电话 / 微信
- 专业能力
- 接单方向
- 稳定性
- 质量评分
- 备注

同时已实现自动统计：

- 接单状态
  - 空闲
  - 接单中
  - 满载
- 当前接单数
- 累计接单数

并支持：

- 编辑老师资料
- 将老师派给当前订单
- 删除老师资料

### 2.8 作者登记表识别

当前已经做了轻量版识别：

- 支持上传 `txt / json / csv`
- 可自动尝试提取：
  - 作者姓名
  - 作者邮箱
  - 作者学历
  - 作者学校
  - 邮编
  - 基金信息
  - 投稿邮箱
  - 投稿邮箱密码
  - 英文作者信息

说明：

- `pdf / doc / docx / xls / xlsx` 当前会先作为附件保存
- 还没有接入真正的 OCR / Word / PDF 解析能力

## 4. 当前已实现的业务流程覆盖

目前已经覆盖你核心业务的大部分教务流程：

1. 客户确认服务后录入基础订单
2. 收集作者登记表
3. 整理作者信息并传老师
4. 派单给老师
5. 区分新老师与稳定老师
6. 新老师创新点审核
7. 初稿审核
8. 编辑老师审查
9. 投稿前作者信息核对
10. 投稿后登记期刊状态
11. 首周查稿
12. 每周查稿
13. 未入 Under Review 时提醒催稿
14. 返修提醒
15. 录用后版面费提醒
16. 校稿提醒
17. Online 提醒
18. 检索提醒
19. 检索审查报告提醒

## 5. 当前仍然属于 v1 原型的限制

以下内容目前还没有正式落地：

- 后端数据库
- 多人实时协同
- 正式权限隔离
- 销售端、主管端、接单老师端独立完整工作台
- 真正的 Word / PDF / 图片 OCR 识别
- 附件云端存储
- 消息提醒自动化
- 微信 / 邮箱 / 任务通知联动
- 登录安全、账号管理、日志审计

## 6. 现在最适合继续做的下一步

建议下一阶段优先级如下：

### 第一优先级

- 把数据从浏览器本地存储迁移到正式数据库
- 做正式登录与权限隔离
- 做订单、老师、作者三张核心数据表

### 第二优先级

- 增加销售端
- 增加主管端
- 增加接单老师汇报端

### 第三优先级

- 接入登记表 OCR / Word / PDF 解析
- 增加自动提醒机制
- 增加导出、截图归档、检索报告归档

## 7. 当前结论

截至目前，这个系统已经不只是静态草图，而是一个可实际演示、可录订单、可做教务跟进、可做老师库管理、可在局域网内部试用的教务端原型。

如果下一步继续推进，最值得做的是：

- 正式数据库化
- 多角色权限化
- 自动提醒化
- 文档识别自动化

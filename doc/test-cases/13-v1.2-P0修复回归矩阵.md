## 二、修复项 A1：operation-logs 越权修复（15 个 action 全部覆盖确认）

**对应修复文档**：`doc/B端-P0修复-01-operation-logs.md`
**修复要点**：
- 类级别加 `@UseGuards(AuthGuard)`
- `list()` 加 `isAdminLike` 角色分支，非 admin/owner 静默覆盖 `userId` 为 `session.userId`
- `findOne()` 加归属校验，非 admin/owner 越权访问统一返 404（不暴露存在性）
- 1 份 controller 改写；service/module 不动

### TC-OPLOG-001：login action 完整覆盖（成功、失败、token 过期、跨端口登录）

| 字段 | 内容 |
|------|------|
| 优先级 | P0 |
| 对应修复项 | A1（operation-logs 越权修复） |
| 修复前行为 | 任意登录用户都能 `GET /api/operation-logs` 拉全表审计日志，存在信息泄露 |
| 修复后行为 | 非 admin/owner 只能看自己产生的日志；admin/owner 可看全表 |
| 自动化建议 | 建议自动化（HTTP + DB 验证） |

**前置条件**：
1. 4 个测试账号：`sales01`（sales）、`staff01`（staff）、`youlun`（admin）、`boss01`（owner）
2. 端口 3000 / 3001 均已启动

**测试步骤**：
1. `POST /api/auth/login` 用 sales01/test123 登录，记录 token，记 T1
2. 5 次故意输错密码，触发 failed_login_count>=5 锁定
3. 故意带过期 token 调用 `GET /api/operation-logs`
4. 端口 3001 登录 owner 后调用 `GET /api/operation-logs`
5. `GET /api/operation-logs?userId=youlun`（sales01 token）

**预期结果**：
- 步骤 1：DB `operation_logs` 新增 `action='login'`, `user_id='sales01'`, `target_type='user'`, `target_id='user-test-sales-01'`
- 步骤 2：DB 新增 5 条 `action='login'`, `detail.result='failure'`, `user_id='sales01'`
- 步骤 3：`GET /api/operation-logs` 返 HTTP 401（AuthGuard 抛 UnauthorizedException）
- 步骤 4：admin/owner 返 HTTP 200，返回全表日志，可按 `?userId=` 过滤
- 步骤 5：sales01 调用返 200，但响应只含 `user_id='user-test-sales-01'` 的记录，`?userId=youlun` 被静默覆盖

**DB 核对 SQL**：
```sql
-- 验证 login 日志
SELECT id, user_id, action, target_type, target_id, detail, created_at
FROM operation_logs
WHERE action='login' AND user_id='user-test-sales-01'
ORDER BY created_at DESC LIMIT 10;
-- 期望至少 6 条（1 成功 + 5 失败）

-- 验证 sales01 视角下无法看 youlun 日志
SELECT COUNT(*) FROM operation_logs WHERE user_id='user-admin-1';
-- 期望 N 条（>0），但 sales01 调 GET 时只看到自己的
```

3. **然后 A3 handover**：依赖 A2
4. **再 A4 collab close**：独立
5. **最后 A5 users/employees**：独立

| 用例范围 | 自动化方式 | 框架 |

## 1. CROSS-1 客资分流字段与销售看板统计

### 1.1 任务背景

```text
数据流（运营端分流 → 销售端不显示）：
  ops_a POST /api/leads { isDispatched: 1 }
  → leads.is_dispatched = 1
  → sales_a GET /api/leads  → 列表中不出现该客资
  → admin_d GET /api/leads?scope=all → 列表中出现该客资
  → ops_a GET /api/leads（自己录入的）→ 列表中出现该客资
```

## 3. CROSS-3 通用提醒接口

### 3.1 任务背景

```text
数据流（销售 → 运营提醒）：
  sales_a POST /api/reminders { recipientId: "USR_OPS_A", recipientRole: "operation",
    relatedType: "lead", relatedId: "LEAD_UND", content: "客资已补充信息" }
  → reminders.service 校验角色/参数
  → notifications.service.create 写入 notifications
  → gateway.emitCreated → socket push notification.created + reminder.created
  → ops_a /admin_d 端 NotificationContext 收到 → 铃铛红点 +1
  → 跨端口「消息中心」列表出现一条
```

### 3.2 关键接口

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/reminders` | AuthGuard | 新建提醒（销售/运营/主管互相提醒）|
| GET | `/api/reminders/unread-count` | AuthGuard | 当前用户的未读提醒数（typeCode='reminder'）|
| PATCH | `/api/reminders/:id/read` | AuthGuard | 标记单条已读（仅本人）|

## 8. 迁移与回滚（关键风险点）

### 8.1 M26 迁移执行清单

```sql
-- 1. leads 表扩展字段（CROSS-1 + CROSS-2）
ALTER TABLE leads
  ADD COLUMN IF NOT EXISTS is_dispatched TINYINT NOT NULL DEFAULT 0,
  ADD COLUMN IF NOT EXISTS client_degree VARCHAR(32) NULL,
  ADD COLUMN IF NOT EXISTS client_major_research VARCHAR(255) NULL,
  ADD COLUMN IF NOT EXISTS client_time_requirement VARCHAR(255) NULL,
  ADD COLUMN IF NOT EXISTS objection_point TEXT NULL,
  ADD COLUMN IF NOT EXISTS follow_action TEXT NULL,
  ADD COLUMN IF NOT EXISTS follow_action_at DATETIME NULL;

-- 2. 索引
CREATE INDEX IF NOT EXISTS idx_leads_is_dispatched ON leads (is_dispatched);
CREATE INDEX IF NOT EXISTS idx_leads_follow_action_at ON leads (follow_action_at);

-- 3. orders 表订单编号（CROSS-4）
ALTER TABLE orders
  ADD COLUMN IF NOT EXISTS order_code VARCHAR(32) NULL;

CREATE UNIQUE INDEX IF NOT EXISTS uk_orders_order_code ON orders (order_code);

-- 4. 订单编号序列表（CROSS-4）
CREATE TABLE IF NOT EXISTS orders_order_code_seq (
  seq_date DATE NOT NULL,
  current_seq INT NOT NULL DEFAULT 0,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (seq_date),
  UNIQUE KEY uk_orders_order_code_seq_date (seq_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 5. 通知 + 收藏表无需迁移（已支持 reminder / account 类型）
-- favorites 表已支持 target_type='account'，无 schema 变更
-- notifications 表已支持 type_code='reminder'，无 schema 变更
```

### 8.2 回滚脚本

```sql
-- 1. 移除 leads 新增字段
ALTER TABLE leads
  DROP COLUMN IF EXISTS is_dispatched,
  DROP COLUMN IF EXISTS client_degree,
  DROP COLUMN IF EXISTS client_major_research,
  DROP COLUMN IF EXISTS client_time_requirement,
  DROP COLUMN IF EXISTS objection_point,
  DROP COLUMN IF EXISTS follow_action,
  DROP COLUMN IF EXISTS follow_action_at;

DROP INDEX IF EXISTS idx_leads_is_dispatched ON leads;
DROP INDEX IF EXISTS idx_leads_follow_action_at ON leads;

-- 2. 移除 orders 新增字段
ALTER TABLE orders DROP COLUMN IF EXISTS order_code;
DROP INDEX IF EXISTS uk_orders_order_code ON orders;

-- 3. 删除序列表
DROP TABLE IF EXISTS orders_order_code_seq;
```

### 8.3 回滚验证

- **CROSS-1 回滚**：销售端所有 leads 查询代码需去掉 `is_dispatched=0` 过滤（fallback 到 v1.2 行为）；运营端无影响。
- **CROSS-2 回滚**：7 字段移除后，7 字段读写接口需 503 或 400「字段已下线」；前端写跟进弹窗隐藏 6 字段 + intentionLevel。
- **CROSS-3 回滚**：POST /api/reminders 接口需下线（移除 controller），前端封装组件隐藏入口；历史 reminder 类型通知保留在 notifications 表。
- **CROSS-4 回滚**：orders.order_code 移除，close-deal 流程不再生成 orderCode，订单编号改由前端/教务手动录入。
- **CROSS-5 回滚**：POST /api/favorites/toggle 强制 targetType='post'（移除 account 分支），前端「我的收藏」页隐藏账号收藏 tab。

## 10. 已知风险与待办

1. **CROSS-3 教务角色是否允许发提醒**：当前实现 ALLOWED_SENDER_ROLES 不含 academic；如需放开，需先确认教务端是否有"跨角色提醒"业务诉求。
2. **CROSS-4 跨时区部署**：当前 generateOrderCode 硬编码 UTC+8；如未来海外部署需改为配置化时区。
3. **CROSS-2 intention_level 老数据中文值兼容**：v1.2 DB 中该字段存中文「高/中/低」，CROSS-2 后英文 high/mid/low 是否需要做迁移脚本统一为英文？（与产品决策）
4. **CROSS-5 销售端「我的收藏」**：v1.3 任务清单限定"运营端 + 主管端"展示账号收藏，销售端是否同步支持待 SUP-1 联动确认。
5. **M26 索引顺序**：idx_leads_is_dispatched 建议采用 `(is_dispatched, assigned_sales_user_id)` 联合索引以覆盖销售端高频查询；需 DBA 评估。

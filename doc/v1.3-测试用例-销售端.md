## 二、测试目标

1. **字段扩展与回写**：验证 SA-1 写跟进弹窗可一次性提交「客户学历 / 客户需求 / 客户专业·研究方向 / 时间要求 / 异议点 / 意向程度 / 具体跟进措施 / 下次跟进时间」等 8 个 leads 字段，提交后既落 `lead_follow_records` 又回写 `leads` 自身，CROSS-2 数据契约对齐。
2. **列表口径与编辑能力**：验证 SA-2 列表字段（IP、联系方式、跟进字段等）显示、SA-3「更新成交状态」「更新意向程度」两枚行内按钮的功能与数据隔离；并验证「今日未添加」红色标签（SA-6）按 `assigned_at >= 当日 00:00 AND add_status = not_added` 口径正确触发与排序置顶。
3. **成交全链路**：验证 SA-7 新菜单、SA-8 成交录入 6 维字段（产品/服务/保障/付款阶段/金额/订单编号）、SA-9 订单流转到教务订单池（`orders` + `order_finance` + `order_follow_records` 三表同步落库与 Socket.IO 推送）。
4. **三角色提醒与菜单结构**：验证 SA-4 销售/运营/主管三角色可互发提醒（`POST /api/reminders`）、落地 notifications + Socket.IO；验证 SA-11 侧边栏一级菜单按「我的客资 / 订单跟进 / 当日待跟进 / 我的成交」四分法调整；验证 SA-10 旧「被动添加」菜单已下线。
5. **跨端联动与数据隔离**：验证分流（OP-5 / CROSS-1）的客资 `is_dispatched=1` 不出现在销售端任何位置；验证订单流转到教务端（AC-1）可在订单池可见；验证主管端（SUP-3）能收到销售发来的提醒。

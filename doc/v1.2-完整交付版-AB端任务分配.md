## 一、版本目标

1.2 不再只是修复问题或打通单条协同链路，而是完整交付四端口协同系统。

核心链路必须达到：

```text
运营录入作品/客资
-> 分配销售
-> 销售跟进和协同
-> 销售标记成交并创建订单
-> 教务接收订单并推进交付
-> 主管查看全局数据、员工、账号、导出和异常
-> 四端口均可收到实时提醒并离线补看
```

本版本必须达到：

- 运营端完整可用：今日任务、排行榜、学习榜单、个人看板、作品录入、客资录入、客资看板、我的作品、作品广场、账号管理。
- 销售端完整可用：我的客资、待跟进、客资详情、协同申请、订单跟进、消息中心。
- 教务端完整可用：订单池、订单详情、进度跟进、节点提醒、异常反馈、导出。
- 主管端完整可用：总览、排行榜、个人看板选择器、作品看板、客资看板、员工管理、账号管理、基础分析看板。
- 数据底座完整：协同状态机、通知表、订单表、订单跟进、导出任务、操作日志、权限隔离、分页筛选排序。
- Excel 导出完整：作品、客资、排行榜、订单、协同记录按权限导出。
- 性能和稳定性达标：50-100 人同时在线，列表分页，异步导出，实时提醒可用。

## 二、A/B 总体分工

| 端 | 主责范围 | 说明 |
| --- | --- | --- |
| A端 | 运营端完整功能 + 主管端完整管理看板 + 作品/账号/排行榜/个人看板/分析口径 | A 端负责运营和主管的核心体验，优先保证数据录入、看板、排行榜、账号员工管理、主管导出入口完整。 |
| B端 | 销售端完整功能 + 教务端完整功能 + 客资/协同/订单/通知/导出/权限状态底座 | B 端负责交易和交付链路，统一维护客资状态机、订单状态机、通知、WebSocket、导出任务和权限过滤。 |
| A/B共同 | 四端口导航、角色权限、接口契约、端到端联调、性能回归、最终验收 | 共享底座必须先定契约，避免 A/B 各自实现字段、状态和跳转。 |

### 2.1 建议主责边界

- A 主责：`posts`、`post_metrics`、`accounts`、`employees`、运营排行榜、个人看板、主管总览、主管作品看板、主管客资看板前端。
- B 主责：`leads`、`lead_follow_records`、`collaboration_tasks`、`orders`、`order_follow_records`、`notifications`、`exports`、`operation_logs`、权限过滤。
- A 可消费 B 的客资、订单、通知接口，但不私自新增状态 code。
- B 可消费 A 的作品、账号、员工接口，但不私自改变排行榜和看板统计口径。

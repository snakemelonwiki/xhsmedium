# 运营中台四端口 — V1.1 运营到销售核心协同版 A/B 任务分配（前端重构版）

> 创建日期：2026-05-31  
> 依据文档：`doc/v1.1-运营到销售核心协同版-AB端任务分配.md`、`doc/运营中台四端口-当前问题.md`、`doc/运营中台四端口.md`  
> 版本定位：在 V1.1 运营到销售核心协同链路基础上，同步启动前端从原始 HTML + vanilla JS 向 React / Next.js + Ant Design Pro 风格后台重构。  
> 适用范围：A/B 两人全栈开发、前端迁移、后端契约、联调、测试验收。

---

## 一、核心结论

原 V1.1 任务分配已经能覆盖“运营录入作品/客资 -> 分配销售 -> 销售跟进 -> 发起协同 -> 运营处理 -> 销售继续跟进”的主链，但它仍默认在现有 `public/index.html` + `public/js/*.js` 上继续补页面。

结合当前问题文档中“页面长时间使用后卡住、请求堆积、表单状态丢失、图片上传影响文本字段”等反馈，以及最终版文档中“React / Next.js + Ant Design Pro 适合 CRM 后台风格，四端口可复用组件”的技术方向，本版本不建议继续在旧前端上大规模新增功能。

重新评估后，本版改为“前端全量迁移版”：

- 后端继续沿用现有 NestJS + TypeORM + MySQL。
- 新建 React / Next.js 前端工程，使用 Ant Design 5 + ProComponents 建 CRM 后台风格界面。
- V1.1 一次完成当前用户可见旧前端页面的迁移，不给普通用户保留新旧两套 UI。
- 运营到销售核心协同链路按新前端重做并作为主验收链路。
- 教务端、主管端、分析看板、导出等已有旧前端入口必须迁到新前端；如果后端能力暂未完整，只迁移当前已有能力和页面壳，不新增超出 V1.1 的复杂业务。
- 旧前端仅保留为代码归档、交互参照和管理员紧急回退，不作为正式用户入口。

## 二、V1.1 新目标

本版本必须同时达成两个目标。

### 2.1 业务目标

```text
运营录入作品/客资
-> 运营分配销售
-> 销售收到新客资提醒
-> 销售查看客资详情并跟进
-> 销售发起运营协同
-> 运营收到协同任务并处理
-> 销售收到处理结果并继续跟进
-> 运营端可回看客资状态变化
```

### 2.2 前端架构目标

```text
旧前端 public/index.html + public/js/*.js
-> 新前端 frontend/ Next.js + TypeScript
-> Ant Design Pro 风格布局
-> 四端口共享登录、权限、导航、表格、筛选、上传、状态标签、消息组件
-> 当前用户可见页面一次性迁移完成
```

本版交付时，以“新前端能否完全替代旧前端用户入口”为基础标准，以“运营到销售核心业务链路能否稳定跑通”为主验收标准。

## 三、前端技术方案

### 3.1 推荐技术栈

| 层级 | 方案 | 说明 |
| --- | --- | --- |
| 框架 | Next.js + React + TypeScript | 新建 `frontend/`，避免与 legacy 前端互相污染。 |
| UI | Ant Design 5 + `@ant-design/pro-components` | 使用 ProLayout、ProTable、ProForm、ProDescriptions、ProCard 做 CRM 后台风格。 |
| 请求 | 统一 API Client | 统一处理 token、401、错误提示、分页参数、请求取消。 |
| 数据缓存 | TanStack Query 或 SWR | 列表、详情、通知未读数使用查询缓存；状态变更后精准失效。 |
| 表单 | Ant Design Form / ProForm | 避免手写 DOM 状态，解决表单丢失和上传清空问题。 |
| 上传 | Ant Design Upload + 独立附件状态 | 图片状态与文本表单状态分离。 |
| 实时提醒 | Socket.IO Client + 轮询兜底 | V1.1 可先轮询，保留 WebSocket 接入点。 |
| 测试 | Vitest + React Testing Library + Playwright | 单元测组件逻辑，Playwright 跑核心链路。 |

### 3.3 旧前端全量迁移原则

- `public/js/*.js` 中的业务逻辑只作为迁移参考，不直接复制大段 DOM 拼接代码。
- 当前用户可见的旧前端页面必须迁移到 `frontend/src/features/*` 或明确合并到新前端其他页面。
- 旧前端只允许做阻断线上使用的紧急修复，不再承接任何正式功能开发。
- V1.1 上线时普通用户默认入口必须进入新前端。
- 旧前端入口只能保留为管理员紧急回退，且不在普通导航中展示。
- 状态枚举、接口字段、权限判断必须由新前端共享常量统一维护，禁止页面内写散落中文状态。

### 3.4 新旧 UI 切换方式

本版不再采用“用户侧长期新旧共存”的策略。开发过程中可以并行存在两个工程，但上线后普通用户只能看到新前端。

#### 3.4.1 对用户侧的原则

- 普通用户不在新旧 UI 之间来回跳。
- 同一个功能不能同时暴露新版入口和旧版入口。
- 旧前端不进入普通用户导航。
- 如果某个旧页面确认不再需要，必须在迁移清单中标记为“合并/废弃”，不能默默遗漏。
- 管理员紧急回退入口只能用于故障处理，不作为日常工作入口。

#### 3.4.2 推荐切换方式

```text
开发期：
旧前端保持可用，新前端走独立端口或独立路径用于开发验收；A/B 按迁移清单逐页对齐。

V1.1 提测期：
测试人员只验收新前端；旧前端仅用于对照功能和数据，不作为通过标准。

V1.1 上线期：
普通用户默认只看到新前端；旧前端普通入口下线或隐藏。

上线后：
旧前端保留一段短期管理员回退窗口；稳定后移除 legacy 入口。
```

#### 3.4.3 路由建议

| 阶段 | 用户入口 | 说明 |
| --- | --- | --- |
| 开发期 | `http://localhost:3002` | 新前端独立启动，便于 A/B 开发。 |
| 提测期 | `/new/*` 或独立新前端域名 | 测试只验收新前端。 |
| V1.1 上线 | 默认入口进入新前端 | 普通用户不再进入旧 UI。 |
| 短期回退期 | `/legacy/*` | 仅管理员可访问，用于故障回退。 |
| 稳定后 | 移除 `/legacy/*` | 旧前端入口下线。 |

## 四、A/B 分工总原则

| 原则 | 执行方式 |
| --- | --- |
| 先契约，后页面 | 先定字段、状态枚举、通知类型、路由权限，再做页面。 |
| 先新前端底座，后业务堆叠 | 不在旧 `leads-monitor.js` 继续堆 V1.1 主流程。 |
| A 偏运营端和前端壳 | A 主责 Next.js 工程壳、运营端页面、主管基础入口。 |
| B 偏销售端和状态机 | B 主责客资状态机、销售端页面、协同/通知接口契约。 |
| 公共组件明确主责 | 表格、表单、上传、状态标签、消息面板要复用，不能各写一套。 |
| 每个阶段都可验收 | 每个里程碑至少能登录、能访问页面、能请求真实接口或 Mock 数据。 |

## 五、P0 开工前必须完成的公共契约

### 7.2 B 端后端任务

## 十四、对外口径

> V1.1 前端重构版不是简单继续补旧页面，而是在保留现有 NestJS 后端的基础上，新建 React / Next.js + Ant Design Pro 风格前端，并一次完成当前用户可见旧前端页面迁移。交付后，普通用户默认只使用新前端；旧前端只作为代码归档、交互参照和管理员短期紧急回退，不作为日常工作入口。业务验收重点仍是运营到销售核心协同链路稳定跑通，同时确保主管、教务、分析、账号、员工、订单等旧有页面不因迁移丢失当前已有能力。

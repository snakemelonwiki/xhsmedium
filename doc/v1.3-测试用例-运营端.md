# 运营端测试用例文档

> **版本**：v1.3  
> **适用端**：运营端 `operation`（与主管端、个人看板等联动）  
> **依据文档**：`doc/v1.3-四端口迭代任务清单.md`（OP-1 ~ OP-19, OP-22 ~ OP-24）  
> **覆盖范围**：个人看板（含多维度切换、名次、效率榜、双平台图表、账号分析）、运营总览/今日任务（指标重构、卡片改造、待办拆分）、客资录入（是否分流）、作品录入（去除截图）、排行榜（流量榜）、学习榜单（双维度、跳账号、主管推荐、删除同类按钮）、作品广场（看全公司）、账号管理（账号隔离）、客资看板（提醒）、我的收藏、作品详情（封面置顶）。  
> **跨端提示**：OP-2、OP-10、OP-17、OP-18、OP-19、OP-23、OP-24 同时影响主管端个人看板；OP-5 / OP-13 / CROSS-1 同时影响销售端和主管端，详见各章节"跨端期望"。

---

## 一、测试目标

1. 运营人员可在个人看板用「指标维度 / 平台 / 时间」三维切换快速定位自己作品的流量/获客情况，切换后所有指标卡和效率榜同步刷新。
2. 运营人员可独立完成客资录入（含「是否分流」），分流的客资不再进入销售统计；运营客资看板可对销售发起提醒。
3. 运营总览/今日任务、个人看板的指标口径统一按 v1.3 重构：流量 = 点赞+评论+收藏；删除「区间作品/区间客资/区间流量/区间成交」卡；新增「总流量/总获客/本月作品数/本月客资数/本月点赞数/本月流量数/获客贴数」。
4. 学习榜单的「主管推荐」「流量/客资维度切换」「查看账号」「删除同类按钮」按 v1.3 规范交付，与主管端 SUP-1 标记的优秀作品保持一致。
5. 运营端账号管理、账号下拉、个人看板、作品/客资录入均按 v1.3 严格隔离：只看到自己负责的账号，不越权查看或编辑他人账号。

## 二、测试账号与基础数据

### 2.1 测试账号

| 角色 | 建议账号 | 用途 |
| --- | --- | --- |
| 运营 A | `operation_a` | 主测试账号，负责小红书/抖音两个平台共 6+ 个账号，录入作品/客资 |
| 运营 B | `operation_b` | 账号隔离对照账号，验证运营 A 看不到其数据 |
| 销售 A | `sales_a` | 接收运营 A 分流的客资，验证 OP-5 销售看板统计排除 `is_dispatched=1` |
| 销售 B | `sales_b` | 接收运营 A 未分流的客资，验证 OP-5 `is_dispatched=0` 的常规流程 |
| 主管 | `supervisor_a` | 用于 OP-10 / SUP-1 标记优秀作品、OP-2 名次基线、OP-3 跨视角对照 |
| 运营主管 | `admin` | 用于校验主管看板汇总 |

### 2.2 基础数据

| 数据 | 规模要求 | 说明 |
| --- | --- | --- |
| 运营 A 账号 | 至少 4 个（小红书 2 + 抖音 2） | 覆盖 OP-15 账号下拉、OP-18/19 双平台图表 |
| 运营 B 账号 | 至少 2 个 | 用于 OP-15 隔离校验 |
| 运营 A 作品 | 至少 50 条，覆盖近 30 天 | 至少 10 条 `is_lead_post=1`，10 条非获客贴，混合小红书/抖音 |

| 主管端标记 | 至少 3 条 `is_supervisor_picked=1` 的作品 | 用于 OP-10 主管推荐 |

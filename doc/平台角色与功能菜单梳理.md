## 一、角色定义

| 角色 code | 中文名 | 可登录端口 | 备注 |
| --- | --- | --- | --- |
| `owner` | 总后台/所有者 | 3001 / 3302 | 最高权限，必须从 3001 或新前端 3302 登录 |
| `admin` | 主管/管理员 | 3000 / 3003 / 3302 | 运营管理，可进统一入口 3003 |
| `supervisor` | 主管 | 3000 / 3003 / 3302 | 与 admin 等价，主推走 3003 |
| `operation` | 运营员工 | 3000 / 3003 / 3302 | 运营端主要角色 |
| `staff` | 运营员工（历史别名） | 3000 / 3003 / 3302 | 与 operation 等价 |
| `sales` | 销售 | 3000 / 3003 / 3302 | 销售端 |
| `academic` | 教务 | 3000 / 3003 / 3302 | 教务端 |
| `academic_supervisor` | 教务主管 | 3000 / 3003 / 3302 | 比普通 academic 多财务字段权限 |

### 角色等价关系

- `staff` == `operation`（运营员工）
- `admin` == `supervisor`（主管）
- `academic_supervisor` 是 `academic` 的增强版

### 角色枚举定义位置

- `backend/src/entities/user.entity.ts`
- `schema.sql` 第 99 行
- `frontend/src/shared/auth/auth.ts`

## 二、登录入口与端口规则

| 端口 | 名称 | 允许角色 | 拒绝角色 |
| --- | --- | --- | --- |
| `3000` | 主入口 | staff/operation/sales/academic/admin/supervisor | owner |
| `3001` | 总后台 | owner | 其他全部角色 |
| `3003` | 统一登录入口 | staff/operation/sales/academic/admin/supervisor | owner |
| `3302` | 新 Next.js 前端 | 全角色（含 owner） | 无 |

### 端口隔离机制

- **L1**：`server.js` Express 中间件（O(1) JWT peek，403）
- **L2**：`auth.service.ts:login`（401 带端口/角色上下文）
- **L3**：`auth.guard.ts:assertRolePortMatch`（任意 /api 命中时 403）

> owner 强制 3001：即使 3003 也在 L2 层拒绝 `role === 'owner'`。

## 六、关键设计特点

1. **没有 `@Roles` 装饰器**：全代码采用 `req.session.role` 内联判断，未使用 NestJS 标准 RolesGuard。
2. **AuthGuard 做入口守卫**：负责 token 校验 + 端口-角色隔离 + 撤销 token 检查。
3. **数据级权限为主**：orders、leads、accounts、posts 等通过业务方法做行级隔离。
4. **财务系统最严格**：finance 模块仅 owner/admin 可访问。
5. **抓取告警最严格**：scraping 模块仅 owner 可访问。
6. **销售端部分接口严格**：`home-summary` 仅 sales；其他销售接口按 userId 过滤数据。

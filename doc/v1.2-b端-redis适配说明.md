# B 端 Redis 适配说明（v1.2 P2-B）

> 对应文档：`v1.2-完整交付版-AB端任务分配.md` §5.2 / §8.4 P2-B "WebSocket + Redis 适配器"

## 现状

- `backend/src/modules/notifications/notifications.gateway.ts` 走默认 socket.io（内存 adapter）。
- 部署形态：当前项目用 PM2 fork 单实例（`ecosystem.config.js`），后端不水平扩展。
- 单实例下默认 socket.io 已可正确向指定 userId 房间广播，无消息丢失。

## 结论

**生产部署接入 `@socket.io/redis-adapter`，本地开发保留单机模式 + 60s 轮询兜底；本次不强行接入 Redis。**

## 强制原因

- 引入 redis-adapter 必然把 `redis://` 写入 `.env`，本地 Node 进程若未起 Redis 服务会在启动期报错。
- 本仓库 `CLAUDE.md` 已说明 MySQL 才是本项目唯一外部依赖，不希望被多一个强依赖污染开发环境。
- 兜底方案（60s 轮询）已能覆盖单人/单角色使用体验，对开发与演示无影响。

## 升级到 Redis Adapter 的推荐做法

未来真正水平扩展 / 多副本部署时，按以下步骤接入：

```bash
cd backend
npm i @socket.io/redis-adapter ioredis
```

```ts
// backend/src/modules/notifications/notifications.module.ts
import { ServerOptions } from 'socket.io';
import { createAdapter } from '@socket.io/redis-adapter';
import { createClient } from 'redis';
// ...
const pubClient = createClient({ url: process.env.REDIS_URL });
const subClient = pubClient.duplicate();
await Promise.all([pubClient.connect(), subClient.connect()]);
io.adapter(createAdapter(pubClient, subClient));
```

环境变量：

```env
REDIS_URL=redis://127.0.0.1:6379
```

## 本地 / 演示环境：60s 轮询兜底

前端 `public/app.js` 的"通知中心"已实现 60s `setInterval(pollNotifications)`，本机演示阶段作为降级通道，不依赖 socket。

如未来需要在不接入 Redis 的情况下支持多副本，请把 polling 间隔收到 5–10s，并保证 `/api/notifications/unread-count` 走 30s 内存缓存（与本文档同级任务 3 的 cache.service.ts 复用）。

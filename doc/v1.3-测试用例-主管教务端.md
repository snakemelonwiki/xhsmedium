## 2. 测试目标

### 2.1 主管端目标

1. 主管作品看板完成「减法」：删除「作品总数 / 获客贴数(≥5) / 待补充建议(≥3 客资)」三张卡，并升级为「时间筛选 + 列排序」交互。
2. 主管可在作品看板对单条作品标记 / 取消标记优秀作品，运营端学习榜单的「主管推荐」板块实时同步。
3. 主管端个人看板的员工选择器切换后，下方所有指标、效率榜、双平台图表、账号分析子菜单都按选中员工数据刷新。
4. 主管可在消息中心、客资看板、订单看板中接收并回复销售/运营发来的跨端口提醒（SA-4 链路）。
5. 主管端所有变更不破坏既有统计口径与权限边界（admin/owner 区分、运营端数据隔离）。

### 2.2 教务端目标

1. 教务端侧边栏/订单池新增「我的成交」入口，仅展示 `deal_status = deal_done` 的订单。
2. 列表字段与销售端 SA-8 录入口径严格一致（订单编号、产品类型、服务类型、保障类型、付款阶段、成交金额、成交销售、负责教务等）。
3. 销售在「我的成交」完成成交录入后，教务端订单池能在 5 秒内通过 Socket.IO 收到新增订单。
4. 教务端对订单只读 / 可分配负责教务，可回复销售发来的提醒。
5. 教务端「我的成交」与既有订单池的「待接收 / 进行中 / 异常」状态机无缝衔接。

### 3.2 基础数据

| 数据 | 要求 |
| --- | --- |
| 员工 | 运营 A/B、销售 A/B、教务 A/B、主管/老板各 1 人，共 ≥ 7 人 |
| 运营账号 | 小红书/抖音各 ≥ 2 个，分别归属运营 A 和运营 B |
| 作品 | **≥ 30 条**（覆盖多平台/多运营/多日期），其中：<br>- 主管推荐样本：**≥ 5 条** 已被主管标记为优秀作品（`is_supervisor_picked = 1`），覆盖不同运营 A/B<br>- 获客贴样本：`is_lead_post = 1` 的作品 ≥ 10 条，关联 leads 数量不等<br>- 普通作品：未标记、且 `is_lead_post = 0` ≥ 8 条<br>- 时间分布：今日、本周、本月、累计各时段均有数据 |
| 客资 | ≥ 20 条，覆盖：未分配、已分配销售 A、已分配销售 B、`is_dispatched = 0/1`、未添加、已添加、已成交 |
| 订单 | **≥ 3 条已成交**（`deal_status = deal_done`），来自不同销售 A/B，订单编号格式 `ORD-YYYYMMDD-XXXXX`；其中：<br>- 1 条已分配负责教务为教务 A<br>- 1 条未分配负责教务（`academic_id IS NULL`），用于 AC-1 分配测试<br>- 1 条已分配负责教务为教务 B（数据隔离用） |
| 订单 | ≥ 5 条非成交订单（待接收、进行中、异常、完成），用于 AC-1 仅展示已成交的过滤校验 |
| 跨端提醒 | 销售 A → 主管的提醒 ≥ 1 条、销售 B → 主管的订单提醒 ≥ 1 条、运营 A → 主管的客资提醒 ≥ 1 条 |
| 主管建议 | 与 `is_supervisor_picked = 1` 的作品一一对应的 `supervisor_suggestions` 记录 ≥ 5 条 |

### 5.3 SUP-1 主管手动标记优秀作品（P0）

> 任务描述：主管端作品看板每行新增「标记优秀作品」按钮（toggle：标记 / 取消标记）。被标记的作品在运营端学习榜单的「主管推荐」板块中展示。数据落 `posts.is_supervisor_picked`（BOOLEAN/TINYINT）+ `supervisor_suggestions` 关联记录。主管端「主管推荐」板块可看到自己标记过的全部作品。

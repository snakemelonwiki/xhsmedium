### 验证查询

```sql
-- 1. posts 90 天统计（按平台）
SELECT platform, COUNT(*) AS posts, SUM(likes) AS likes_sum
  FROM posts
 WHERE employee_id = 'emp-3d64d870-862a-4947-8134-b92e4f75a01c'
   AND published_at >= DATE_SUB(CURDATE(), INTERVAL 90 DAY)
 GROUP BY platform;

-- 2. leads 90 天统计（按平台 + deal 数）
SELECT platform, COUNT(*) AS leads,
       SUM(CASE WHEN deal_status='deal' THEN 1 ELSE 0 END) AS deals
  FROM leads
 WHERE employee_id = 'emp-3d64d870-862a-4947-8134-b92e4f75a01c'
   AND created_at >= DATE_SUB(NOW(), INTERVAL 90 DAY)
 GROUP BY platform;

-- 3. post_metrics 每日聚合（90 天）
-- 注意：posts.id 与 post_metrics.post_id 是不同 collation，JOIN 时显式指定
SELECT pm.date, SUM(pm.likes) AS likes, SUM(pm.comments) AS cm, SUM(pm.favorites) AS fav
  FROM post_metrics pm
  JOIN posts p ON p.id = pm.post_id COLLATE utf8mb4_0900_ai_ci
 WHERE p.employee_id = 'emp-3d64d870-862a-4947-8134-b92e4f75a01c'
   AND pm.date >= DATE_SUB(CURDATE(), INTERVAL 90 DAY)
 GROUP BY pm.date ORDER BY pm.date;

-- 4. 乱码校验（HEX 抽样）
SELECT id, HEX(nickname), nickname FROM leads  WHERE id LIKE 'lead-mgxq-%' LIMIT 5;
SELECT id, HEX(title),    title    FROM posts  WHERE id LIKE 'post-mgxq-%' LIMIT 5;
-- 结论：抽样 5+5 条全部不含 `EFBFBD`，中文 UTF-8 正常
```

### OP-25 全部账号排序（默认按活跃度分数降序）

- **问题描述**: 运营端 `/operation/dashboard/account-analysis` 页面（`frontend/src/app/operation/dashboard/account-analysis/page.tsx`）调用 `GET /api/dashboard/personal/accounts/timeseries?days=N`，后端 `backend/src/modules/dashboard/dashboard.service.ts:914` 原 SQL **无 ORDER BY**，DB 返回顺序 = 物理插入顺序（按主键 id 升序），导致空账号 / 很久没发账号 / 爆款账号混杂，运营看不到"重点账号"。
- **修复**: 在 `dashboard.service.ts:914-947` 重写 SQL，LEFT JOIN posts / leads 子查询 + 计算活跃度分数 + ORDER BY 排序。
  - **score = has_recent_posts * 1000 + total_recent_leads * 50 + post_count_in_range * 10 + total_traffic / 100**
  - 三级排序：`ORDER BY score DESC, a.account_name ASC, a.id ASC`
  - JOIN 处显式 `COLLATE utf8mb4_unicode_ci`（`posts.id` 是 `utf8mb4_0900_ai_ci`、`accounts.id` 是 `utf8mb4_unicode_ci`，不一致会触发 1267 errno）
  - params 顺序：`[from, to, from, to, employeeId, platform?]`，对应 SQL 里的 `published_at BETWEEN ? AND ?` + `created_at BETWEEN ? AND ?` + `a.employee_id = ?` [+ `a.platform = ?`]
- **关键 SQL diff**（仅修改 `computeAllAccountsTimeSeries` 的 `accountRows` 查询段）：

  ```sql
  -- 修复前: 无 LEFT JOIN、无聚合、无 ORDER BY
  SELECT a.id, a.account_name AS accountName, a.platform, a.posting_plan AS postingPlan,
         a.persona, a.positioning
    FROM accounts a
   WHERE a.employee_id = ? ${accountWhere}

  -- 修复后: LEFT JOIN posts/leads 子查询 + 活跃度分 + ORDER BY
  SELECT a.id, a.account_name AS accountName, a.platform, a.posting_plan AS postingPlan,
         a.persona, a.positioning,
         COALESCE(p_agg.has_recent_posts, 0) AS has_recent_posts,
         COALESCE(p_agg.post_count, 0) AS post_count,
         COALESCE(p_agg.total_traffic, 0) AS total_traffic,
         COALESCE(l_agg.total_leads, 0) AS total_leads,
         (COALESCE(p_agg.has_recent_posts, 0) * 1000
           + COALESCE(l_agg.total_leads, 0) * 50
           + COALESCE(p_agg.post_count, 0) * 10
           + COALESCE(p_agg.total_traffic, 0) / 100) AS score
    FROM accounts a
    LEFT JOIN (
      SELECT account_id, COUNT(*) AS post_count,
             (CASE WHEN COUNT(*) > 0 THEN 1 ELSE 0 END) AS has_recent_posts,
             COALESCE(SUM(likes + comments + favorites), 0) AS total_traffic
        FROM posts
       WHERE published_at BETWEEN ? AND ?
       GROUP BY account_id
    ) p_agg ON p_agg.account_id COLLATE utf8mb4_unicode_ci = a.id COLLATE utf8mb4_unicode_ci
    LEFT JOIN (
      SELECT account_id, COUNT(*) AS total_leads
        FROM leads
       WHERE created_at BETWEEN ? AND ?
       GROUP BY account_id
    ) l_agg ON l_agg.account_id COLLATE utf8mb4_unicode_ci = a.id COLLATE utf8mb4_unicode_ci
   WHERE a.employee_id = ? ${accountWhere}
   ORDER BY score DESC, a.account_name ASC, a.id ASC
  ```

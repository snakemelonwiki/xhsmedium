# #10 性能加固 - 代码核对报告

| 序号 | 需求项 | 判定 | 证据/缺失说明 |
|---|---|---|---|
| 1 | 录入页长时间停留不得出现卡死、按钮无响应、表单无法提交 | ⚠️ 部分满足 | viewCleanup 机制可清理定时器/请求避免累积卡死；草稿自动保存防闪退。但无提交按钮防重复点击（submitPost/submitLead 无 disabled 锁），长时间停留后 Token 过期（2h）会导致提交 401 失败且无自动续期 |
| 2 | 所有列表必须分页加载，默认每页20条 | ❌ 未满足 | 后端 posts.findAll()、leads.findAll() 均为全量查询无分页；前端 loadData() 一次性拉取全部 posts/leads/accounts/employees 到内存；仅 leads.listFollowRecords 有 take/skip 分页 |
| 3 | 图片必须懒加载，缩略图和原图分离 | ❌ 未满足 | 前端 img 标签无 loading="lazy" 属性，无 IntersectionObserver 实现，无缩略图/原图分离机制；所有封面图直接用原图 URL 渲染 |
| 4 | 前端请求必须防抖，避免重复提交和重复刷新 | ⚠️ 部分满足 | 搜索框有 debounce(250)；草稿保存有 debounce(400/1000)；但表单提交（submitPost/submitLead）无防抖/防重复点击锁；仅刷新指标按钮有 disabled 锁 |
| 5 | 长时间会话需要自动续期，Token失效时先保存草稿再提示重新登录 | ❌ 未满足 | JWT 固定 2h 过期（app.module.ts），无 refresh token 机制，无自动续期逻辑；api() 函数遇 401 直接 throw Error，无草稿保存+重登录引导流程 |
| 6 | WebSocket断开后自动重连，不得影响表单填写 | ❌ 未满足 | 虽然 package.json 有 @nestjs/websockets + socket.io 依赖，但后端无任何 Gateway 实现文件，前端无 socket.io 客户端连接代码；WebSocket 功能完全未实现 |
| 7 | 页面组件卸载时必须清理定时器、监听器、未完成请求 | ✅ 已满足 | viewCleanup 对象提供 addInterval/addAbort/add 登记机制；renderApp() 顶部每次切换视图前调用 viewCleanup.runAll() 统一清理 |
| 8 | 30-50人同时在线时首页和列表页响应<2s，提交保存<3s | ❌ 未满足 | 全量查询无分页、无缓存、无索引优化证据；后端 findAll() 无 limit；Playwright 抓取在主线程同步执行可能阻塞；无压测报告或性能基线 |

## 详细分析

### 序号2 - 分页未实现

**后端证据：**
- `backend/src/modules/posts/posts.service.ts:18-19`：`findAll()` 直接 `this.postRepository.find({ order: ... })`，无 take/skip
- `backend/src/modules/leads/leads.service.ts:58-59`：`findAll()` 同样全量查询
- `backend/src/modules/posts/posts.controller.ts:28-29`：GET /api/posts 返回全量数据

**前端证据：**
- `public/js/auth.js:35-36`：`loadData()` 中 `api("/api/posts")` 和 `api("/api/leads")` 一次性拉取全部
- 列表渲染（renderPostsMonitor、renderLeadsMonitor）在内存中 filter 后直接 `.map()` 渲染全部匹配项，无前端分页组件

### 序号3 - 图片懒加载未实现

- `public/index.html` 无 `loading="lazy"` 属性
- 搜索整个 public 目录无 `IntersectionObserver` 或 `lazyload` 相关代码
- 卡片中 `<img src="${item.coverImageUrl}">` 直接加载原图，无缩略图 URL 生成逻辑

### 序号5 - Token 续期未实现

- `backend/src/app.module.ts:64`：JWT 过期时间为 `config.get('JWT_EXPIRES_IN', '2h')`
- `backend/src/shared/middleware/session.middleware.ts:36`：token 验证失败时静默放行（不拦截），但也不续期
- `public/js/api.js:16-18`：api() 函数遇到非 200 响应直接 throw，无 401 特殊处理
- 无 `/api/auth/refresh` 端点，无前端定时续期逻辑

### 序号6 - WebSocket 未实现

- `backend/package.json` 有 `@nestjs/websockets`、`@nestjs/platform-socket.io`、`socket.io` 依赖
- 但 `backend/src/` 下无任何 `*gateway*` 或 `*socket*` 文件
- 前端无 `io()` 或 `new WebSocket()` 调用
- 通知功能（notifications）走的是 HTTP 轮询而非 WebSocket 推送

### 序号8 - 性能基线无保障

- 全量查询 + 无分页 = 数据量增长后响应时间线性增长
- 无 Redis 缓存层（虽有 @socket.io/redis-adapter 依赖但未使用）
- Playwright 抓取在 NestJS 主线程同步执行（15s 超时），会阻塞其他请求

# #11 图片与表单解耦 - 代码核对报告

| 序号 | 需求项 | 判定 | 证据/缺失说明 |
|---|---|---|---|
| 1 | 图片上传组件必须与表单文本状态完全解耦 | ✅ 已满足 | 作品录入：封面上传区（#postCoverUploader）独立于 form#postForm，通过 state.postCoverFile 管理，rerenderPostCoverUploader() 仅重渲染封面区不动表单 |
| 2 | 选择/重选/删除/预览图片都不得清空已填字段 | ✅ 已满足 | setPendingPostCover() 仅操作 state.postCoverFile/postCoverPreviewUrl/postCoverUploadError，不触碰表单字段；rerenderPostCoverUploader() 只替换 #postCoverUploader 的 innerHTML；删除封面调用 clearPendingPostCover() 同样不动表单 |
| 3 | 图片上传失败时只提示图片失败，文本信息仍然保留 | ✅ 已满足 | setPendingPostCover() 校验失败时仅设 state.postCoverUploadError 并 return false，不清空表单；submitPost() 中 API 失败时 setFlash("warn") 提示但保留所有已填字段（不调 form.reset()） |
| 4 | 作品录入和客资录入均适用该规则 | ⚠️ 部分满足 | 作品录入完全解耦（独立 uploader + rerenderPostCoverUploader）；客资录入的图片选择通过 setPendingLeadCapture() 管理 state，不清空表单字段，但客资录入的图片区仍在 form 内部（#leadCaptureInput 在 form#leadForm 内），且选择图片后调用 renderApp() 会整页重渲染 |

## 详细分析

### 序号1 - 作品录入解耦实现

**代码位置：** `public/js/posts-monitor.js:260-267`

作品录入表单结构：
```
<div id="postCoverUploader">  ← 封面上传区，独立于 form
  <input id="postCoverInput" type="file" />
  ...
</div>
<form id="postForm">  ← 文本表单，不含 file input
  ...
</form>
```

关键函数：
- `rerenderPostCoverUploader()`（第440-498行）：仅替换 `#postCoverUploader` 的 innerHTML，不触碰 `#postForm`
- `setPendingPostCover(file)`（state.js:158-172）：仅操作 `state.postCoverFile`、`state.postCoverPreviewUrl`、`state.postCoverUploadError`
- `clearPendingPostCover()`（state.js:141-148）：仅清理封面相关 state

### 序号4 - 客资录入解耦程度

**代码位置：** `public/js/leads-monitor.js:926-960`

客资录入的图片处理：
- `setPendingLeadCapture(file)`（state.js:175-183）：仅操作 `state.leadCaptureFile` 和 `state.leadCapturePreviewUrl`，不清空表单字段 — 满足"不清空已填字段"
- 但 `#leadCaptureInput` 仍在 `<form id="leadForm">` 内部，未像作品录入那样物理分离
- 选择图片后（app.js:331-339）调用 `renderApp()` 整页重渲染，虽然 state 中的表单值会通过草稿恢复机制保留，但实现方式不如作品录入的局部重渲染干净
- 客资录入无独立的 `rerenderLeadCaptureUploader()` 函数，无法做到"仅重渲染图片区"

**结论：** 客资录入在功能层面满足"图片操作不清空文本"（因为 state 独立管理），但架构层面未做到与作品录入同等程度的物理解耦。

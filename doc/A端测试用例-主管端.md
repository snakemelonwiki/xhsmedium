# A端测试用例文档 - 主管端

> 版本：v1.2 完整交付版  
> 适用端：主管端 `admin / owner`  
> 依据文档：`doc/运营中台四端口-当前问题.md`、`doc/运营中台四端口.md`、`doc/v1.2-完整交付版-AB端任务分配.md`  
> 覆盖范围：主管总览、运营排行榜、个人看板选择器、作品看板、客资看板、员工管理、账号管理、基础分析看板、消息中心、导出中心、权限、安全、性能和跨端联调。

## 一、测试目标

主管端验收目标是确认管理者可以用统一口径看全局、看个人、管员工、管账号、追踪异常并导出数据：

1. 主管能登录并查看全局数据。
2. 总览、排行榜、个人看板、作品看板、客资看板统计口径一致。
3. 主管可以管理员工、登录账号、运营账号，且停用/改派影响正确。
4. 主管可以查看协同超时、客资积压、账号异常、员工低更新等风险。
5. 主管可以按当前筛选导出作品、客资、排行榜、订单、协同记录、账号等数据。
6. 主管端具备全局视角，但仍需要对操作留痕、删除停用可追踪、敏感导出有权限边界。

## 二、测试账号与基础数据

### 2.1 测试账号

| 角色 | 建议账号 | 用途 |
| --- | --- | --- |
| 主管 | `admin` | 主管端主测试账号 |
| 老板/高级主管 | `owner` | 校验 owner 入口和高级权限 |
| 运营 A | `operation_a` | 被查看、被建议、被筛选、被停用对照 |
| 运营 B | `operation_b` | 数据隔离和多员工排名对照 |
| 销售 A/B | `sales_a`、`sales_b` | 客资分配、改派、销售筛选 |
| 教务 A | `academic_a` | 订单和教务筛选对照 |

### 2.2 基础数据

| 数据 | 要求 |
| --- | --- |
| 员工 | 运营、销售、教务、主管至少各 1 人；包含启用、停用、未绑定登录账号三类 |
| 运营账号 | 小红书/抖音各不少于 2 个，分别归属不同运营 |
| 作品 | 至少 100 条，覆盖多员工、多账号、多类型、有/无客资、有/无主管建议、优秀/普通 |
| 客资 | 至少 100 条，覆盖新客资、已分配、待添加、未通过、协同中、已通过、已成交、无效 |
| 订单 | 至少 20 条，覆盖待接收、进行中、异常、完成 |
| 协同任务 | 包含待处理、已处理、超时、再次提醒 |
| 导出任务 | 包含 posts、leads、rankings、orders、collaborations、accounts，多状态 |

## 三、优先级说明

| 优先级 | 含义 |
| --- | --- |
| P0 | 不通过不能交付；涉及主管登录、全局可见、权限、员工账号管理、导出、安全 |
| P1 | 影响管理效率；涉及筛选、分页、统计口径、消息、建议、异常 |
| P2 | 体验完善；涉及空状态、展示细节、排序、辅助说明 |

## 八、主管端验收通过标准

主管端交付前至少满足：

- P0 用例全部通过。
- P1 用例通过率不低于 95%，未通过项必须有明确上线风险说明。
- 总览、排行榜、个人看板、作品看板、客资看板在同一周期下统计口径一致。
- 员工管理、账号管理、改派销售、主管建议、导出任务均写入操作日志。
- 所有列表分页加载，主管全局筛选大数据时不明显卡顿。
- 主管可以导出全局作品、客资、排行榜、订单、协同记录、账号，且导出范围与当前筛选一致。
- 普通运营、销售、教务无法通过改 URL 或接口参数访问主管端全量数据。
